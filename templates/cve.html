VULNERABILITY CASE STUDY

CVE-2025-6514

OS command injection risk in the npm package mcp-remote.

What is the problem?

CVE-2025-6514 concerns an OS command injection vulnerability in affected versions of the npm package mcp-remote. The unsafe flow involves OAuth metadata received while connecting to an MCP server: a crafted authorization_endpoint value from an untrusted server could reach command-construction/execution logic without safe handling. If exploited in a vulnerable client environment, this could cause commands to be executed with the privileges of the process running the client.

The core security lesson is that metadata received from a remote server must be treated as untrusted input. URLs should be parsed and validated, and must never be concatenated into operating-system command strings. Prefer safe process APIs with argument arrays where process invocation is genuinely required.

Reported vulnerability facts

  • Package: mcp-remote (npm)
  • Affected versions: 0.0.5 through 0.1.15
  • Fixed version: 0.1.16
  • Weakness: CWE-78 — Improper Neutralization of Special Elements used in an OS Command
  • Reported CVSS v3.1 score: 9.6 (Critical)

Recommended action: update to mcp-remote 0.1.16 or later and verify the actual resolved version in lockfiles and deployed environments.

How MCP-CanaryTrap addresses the case study

  1. Safe vulnerable-flow simulation models the unsafe trust decision without running a shell command or a live exploit.
  2. Dependency/config auditor searches local manifests, lockfiles and MCP client configuration references for mcp-remote.
  3. Runtime URL policy validator demonstrates a defensive HTTPS and input-validation policy for authorization endpoints.
  4. MCP decoy monitor independently records configured decoy-tool interactions in its instrumented MCP server.

Important scope: this is an educational assessment prototype, not a patch for mcp-remote, not proof that a third-party client is secure, and not a passive monitor of arbitrary MCP servers.
