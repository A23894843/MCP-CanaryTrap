Deterministic controls

Protection Rules

These are advanced settings for people managing MCP server connections. You can define what is allowed, register approved servers, run checks, and review whether the activity log has been altered. No AI or machine learning is used.

Rule-based

Access context

If API-key RBAC is configured on the server, provide a key for this browser tab. The key is kept in sessionStorage only. Production dashboard Basic Auth is separate.

Create policy rule

DENY blocks matching tools/call, resources/read or prompts/get requests passing through the HTTP/stdio gateway. Use exact targets or a trailing wildcard, e.g. canarytrap://secret/*.

Register MCP server

Inventory is an operator-maintained register. Reconcile compares it to configured HTTP gateway connections; it is not whole-network discovery.

Webhook alerts

Optional HTTPS webhook for observed decoy access or an enforced DENY policy. Keep the receiver private and validate requests there; the current prototype sends minimal metadata and does not sign webhook payloads.

Security operations

No live attack traffic
Choose a security operation to view its JSON result.

Limitations: hash chaining is tamper-evident but not immutable if an attacker controls the database; export hashes to independent storage for stronger assurance. Webhook alerts contain minimal metadata only. Compliance output is a self-assessment, not certification.

What do the results mean?

●
CLEAN

No submitted interaction matched the configured decoy list in this test case.

●
FLAGGED

At least one submitted interaction target matched a configured decoy identifier.

●
Important limitation

A CLEAN result only describes the actions CanaryTrap actually checked. It does not prove that an entire server or system is safe.

Quick glossary — plain English

🪤
Decoy

A made-up tool or item used as a tripwire during a test. It should never contain real private information.

⚠
Flagged

A test action touched one of the decoys you told CanaryTrap to watch. It is a warning about the test, not automatic proof of malicious intent.

✓
Clean

None of the actions supplied to this test matched a watched decoy. It does not mean unobserved activity is safe.

⇄
Gateway

A checkpoint between a client and a server. CanaryTrap can inspect supported traffic only when it passes through this checkpoint.

🔌
MCP server

A program that makes tools, resources, or prompts available to an AI application or another client.

🧾
Activity record

A saved note about an action processed by a test or supported gateway. It helps explain how a result was reached.

What this prototype does and does not do

Implemented in this prototype

  • Built-in simulated benign and overreaching scenarios.
  • Structured custom test cases with configurable decoy targets.
  • Deterministic decoy-target matching.
  • SQLite-backed session and event records.
  • Dashboard views for sessions, events, and returned evidence.

Not yet established

  • Automatic interception of arbitrary third-party MCP traffic.
  • Monitoring of connections that bypass the defined monitoring point.
  • Enterprise SSO/OIDC, role-based authorization, and MFA (a minimal HTTP Basic guard is included for controlled pilots).
  • Enterprise-scale performance, resilience, or independent security validation.
  • Proof that every decoy interaction necessarily represents malicious intent.

Use fabricated identifiers and synthetic data only. Do not enter actual credentials, personal data, or confidential company information into demonstration tests.

Live integration / Transport adapters

Connect a Server

This advanced page lets you route a supported MCP server connection through CanaryTrap. A gateway is a checkpoint between a client and a server. Only traffic routed through this configured checkpoint can be inspected.

HTTP + STDIO

Streamable HTTP connection

Fill in the endpoint and decoys. This browser form generates a configuration snippet locally; it does not store upstream URLs or credentials on the server.

Use a short name with letters, numbers, dashes, or underscores. It identifies this connection in the configuration.

Enter the address provided by the server administrator. Only connect to servers you trust.

Enter only the variable name, not the password or token itself. Add the actual secret in your server or hosting provider settings.

Local stdio connection

The stdio proxy must run on the same machine/container as the downstream MCP server. Do not enter arbitrary shell commands into a publicly exposed dashboard.

Only use a start command provided by someone you trust. This can launch a program on the server machine; do not paste secrets here or expose this setting to untrusted users.

Safety boundary

HTTP upstream definitions are loaded from CANARYTRAP_HTTP_UPSTREAMS. Credentials are referenced by environment-variable name. Stdio starts a local child process, so restrict it to trusted server commands and run the gateway with least privilege.

Settings & Deployment

Prepare the settings needed to run CanaryTrap on your own computer or a hosting service. This page creates a plan; it does not deploy the application for you.

CONFIGURATION WIZARD
Before you continue: This page creates setup files and instructions; it does not deploy automatically. Do not paste API keys or passwords into this page unless you understand where the downloaded file will be stored. Configure connection secrets on your server or hosting provider, and route only trusted test servers through the gateway.

1Deployment target

Choose how you plan to run the service.

Render is the guided hosted path; Docker is for your own server or lab.

Needed to construct the hosting-provider deploy link. Push this project, including render.yaml, first.

2Dashboard access

Choose credentials for the production dashboard.

Use a unique password of at least 16 characters. The generated file contains this password—keep it private and never commit it to Git.

Use persistent storage. On Render, a persistent disk is required to retain SQLite data across deploys.
